# Інженерне оновлення v1.1 — 9 жовтня 2026

## Початковий стан і обсяг

База: `main` 63f7d58 після PR #1. У хмарному робочому середовищі відтворено
77 синтетичних тестів, Ruff і pip-audit; останній CI main був успішним.
Особиста SQLite та localhost власника не перенесені. Оновлення не розгортає сайт,
не створює акаунти й не змінює моделі або історичні ML-звіти.

Виявлені прогалини: відсутність політик для контриб'юторів і приватного повідомлення
про вразливості, Windows/coverage/CodeQL у CI; операції профілю всередині великого UI;
нестандартизована обробка пошкодженої автопам'яті; повторні обчислення пояснень і MMR.
Ризики рефакторингу: rerun/autosave, Undo, різні значення watched/not_seen/watchlist,
схеми профілю 2–5, канонічні ID, обидві мови й незмінність ранжування.

## Реалізовані зміни

1. CONTRIBUTING, SECURITY, CHANGELOG, архітектура, налаштування розробки, компактний
   Quick Start та коректні CI/Python/MIT бейджі. Збережено існуючі UK/EN інструкції.
2. Dependabot для Python/Actions, Python CodeQL security-extended, шаблони issue/PR,
   мінімальні permissions, прив'язані до SHA actions, timeout і скасування старих CI.
   У фінальному пакеті checkout/setup-python оновлено до v6 після спостереженого
   Node20 deprecation warning; SHA перевірено за офіційними тегами.
3. Матриця Linux 3.10/3.11 та Windows 3.11, coverage без довільного порога, аудит
   залежностей; поступові Mypy/import/format перевірки й локальні pre-commit hooks.
4. `src/profile_actions.py`: незалежні від Streamlit операції заміни, оцінки, watched,
   скасування та Undo; копії стану для ізоляції. UI зберігає widgets/rerun/autosave.
5. Автопам'ять використовує обмежений JSON-парсер із перевіркою дублікатів,
   non-finite констант і глибокого вкладення; пошкоджений рядок не переписується.
6. Пояснення обчислюють жанровий контекст один раз на список; MMR повторно використовує
   впорядковані features. Пошук не створює невикористані назви й готує українські назви
   лише для непорожнього запиту після фільтрів. Додано автономний performance-скрипт.

## Виправлені помилки та регресійні перевірки

- Windows CI виявив читання UTF-8 JSON у системному кодуванні в тесті PR #1;
  тест тепер явно використовує UTF-8. Продуктовий запис metadata вже був UTF-8.
- Глибокий/неоднозначний JSON автопам'яті тепер дає контрольовану помилку,
  сумісну з існуючим механізмом відновлення UI, без перезапису SQLite.
- Скасування watched-діалогу зберігає оцінку, внесену після відкриття, і не порушує
  інваріант «оцінені належать до watched».
- Перевірено Undo після редагування, ізоляцію двох сесій/баз, snapshots/cache copies,
  транзакційний rollback і відновлення, старі схеми, SQL-параметри, пошук watched у
  двох мовах, fallback пошкоджених артефактів і оновлення кешу після їх виправлення.
- Еквівалентність MMR перевірена на порожніх/малих підмножинах, ties і чотирьох
  значеннях diversity; пояснення/оцінки — для семи алгоритмів у двох мовах.

## Вимірювання продуктивності

Синтетичні 1500 фільмів, 100 користувачів, 2400 оцінок; ALS 8 factors/3 epochs;
Python 3.11.17, NumPy 1.26.4, Linux, OPENBLAS_NUM_THREADS=1. Рекомендації: три
початкові оцінки, diversity=0.5, 30 warmed samples; UI: 5 warmed reruns. Окремий
MMR: 10000 candidates × 19 features, Top-10. До/після виконано послідовно на одному
хмарному хості без паралельного pytest. [Сирі дані](../reports/performance_v11.json).

| Метрика | До | Після |
|---|---:|---:|
| Adaptive, медіана | 1.714 мс | 1.151 мс |
| Hybrid, медіана | 1.980 мс | 1.412 мс |
| Content-based, медіана | 1.833 мс | 1.247 мс |
| MMR 10000, медіана | 3.203 мс | 1.570 мс |
| Перший AppTest render | 340.76 мс | 337.38 мс |
| Warm UI rerun, медіана | 53.30 мс | 49.84 мс |
| Engine initialization | 41.42 мс | 41.37 мс |
| SQLite write, медіана | 0.190 мс | 0.175 мс |
| Peak process RSS, включно з AppTest | 235.52 MiB | 234.39 MiB |
| MMR peak tracemalloc | 2011976 B | 2171696 B |

MMR приблизно на 51% швидший, рекомендації на 29–33%. Тимчасовий пік MMR зріс
на 159720 B (~0.16 MB): довше живе одна впорядкована копія. Це явний компроміс
пам'яті й швидкості. Зміни RAM/SQLite/запуску невеликі; для них не заявлено доведеної
оптимізації. Перший render виключає запуск Python/imports, мережу й браузер; це
не час старту живого сервера. Одна paired сесія не гарантує такі затримки на ПК.

SHA-256 JSON рекомендацій (ID, score, reason та інші поля) однаковий до/після:
`a6aba7a471544dd857421d800b38ff79e6e12f9ea73c0a5fdd2b0ac9e952a3c1`.
Формули, політика й артефакти ML-бенчмарків не змінені. Незалежний MovieLens
результат +13.3% NDCG@10 стосується тільки трьох початкових оцінок; для 5/10
поліпшення немає. Це не оцінка серіалів або задоволеності живого користувача.

## Безпека, обмеження й ручні дії

Повторно перевірено SQL, JSON, URL/HTML, allowlist ZIP та розміри, model
allow_pickle=False, виключення секретів/даних, Docker і права Actions.
Нових підтверджених вразливостей у перевірених шляхах не виявлено, окрім посиленої
обробки JSON автопам'яті; це цільове ревю, не пентест чи сертифікація.
CodeQL success підтверджує виконання аналізу, а не відсутність усіх можливих findings.
API списку code-scanning alerts недоступний цьому конектору; власнику слід
переглянути самі alerts у Security → Code scanning.

Docker у робочому середовищі недоступний: нову збірку не відтворено. Windows
перевірено на GitHub Actions, не локально. Приватних каталогів, моделей і баз у
хмарі немає; персональну поведінку на них не перевірено. Публічного розгортання
і перевірки реального браузера цього разу не було; UI перевірений AppTest.

Власнику: переглянути й зливати PR послідовно #2 → #3 → фінальний performance PR,
перенацілюючи наступний PR на main після попереднього; не видаляти наступну базову
гілку завчасно. Перевірити [branch protection/private reporting/secret scanning/
push protection](github-maintenance.md). Ці налаштування не оголошено ввімкненими.
Після злиття на ПК: git pull, оновлення залежностей і перезапуск; база не переноситься.

Залишкові ризики: SQLite є пам'яттю інсталяції без акаунтів; немає public tenant
isolation/rate limiting. Каталоги й артефакти — trusted local inputs. UI залишається
великим і лише частково типізованим; ресурсні кеші обмежені кількістю, не RAM quota.
Службові CLI потребують подальших offline integration tests. Dependabot PR потребують
людського перегляду; нові action/dependency revisions потребують регулярної перевірки.

## Оцінка зрілості та v1.2

| Критерій | Інженерна оцінка після змін |
|---|---|
| Оформлення та супровід | Добра основа open-source: політики, CI, інструкції й прозорі обмеження |
| Архітектура | Кращі межі UI/стану; поступові типи, без зайвої інфраструктури |
| Надійність | Сильні синтетичні регресії; реальні приватні дані не перевірялися |
| Безпека | Посилена для локального призначення; не готовність до публічного multi-user |
| Performance | Виміряний виграш ранжування, чесно вказаний memory tradeoff |
| ML evidence | Відтворюваний film benchmark із вузьким scope; серіали/live не оцінені |

Це суб'єктивна інженерна оцінка, не сертифікація. Для v1.2: окремий дослідницький
протокол з larger/independent cohorts, confidence intervals і зафіксованим test set;
вивчити, чому 5/10 seed ratings не поліпшили popularity; вимірювати coverage/diversity
і якість cold items. Для серіалів спочатку потрібні легальні interaction data й окрема
оцінка. Live feedback потребує згоди користувачів та дизайну приватності. Нові
алгоритми й твердження про якість мають пройти цей протокол до інтеграції.
